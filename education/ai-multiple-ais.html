Explore the idea in ChatGPT
Use the first conversation to clarify the user, problem, constraints, and edge cases. A second tool does not automatically share that conversation. Carry the facts that matter into the handoff.
Worked example
“Build a shift log” leaves key questions open. Who posts a change? Who confirms reading it? Can an entry be corrected? For a first version, the opening lead only needs to see unacknowledged items from the previous shift.

Exercise 2 of 3
Hand a lean prompt to Grok
A meta-prompt asks one assistant to write instructions for another. Copy the assembled meta-prompt below into ChatGPT. Then take the prompt it produces into a fresh Grok conversation. A learner can use two other approved tools for the same roles.
Worked example
Vague handoff: “Use our plan above.” Portable handoff: “A closing lead logs a change; the opening lead confirms it. For the pilot, support one store and a single acknowledgement. Flag retention as undecided.”
Your turn
The studio inserts your project context into the master meta-prompt from the library. Read the finished handoff as if you had never seen the first conversation.
Your meta-prompt for ChatGPT
I have been developing this idea with you: [paste developed idea or clear summary]

Please create a single, lean, and highly structured prompt that I can copy and paste into Grok to generate professional software requirements.

The prompt you create must:
- Be concise — no unnecessary preamble or fluff
- Instruct Grok to act as an expert product manager and technical architect
- Request exactly these sections:
  1. Executive Summary (3–5 sentences)
  2. User Personas (2–3)
  3. Functional Requirements (numbered user stories with acceptance criteria)
  4. Non-Functional Requirements (performance, security, scalability, reliability, etc.)
  5. Technical Constraints and Assumptions
  6. Out of Scope
  7. Open Questions
- Emphasize precision, completeness, and developer-readiness
- Tell Grok to flag any ambiguities or missing information explicitly
- Output the finished prompt inside a clean code block so it is easy to copy

Make the prompt as tight and effective as possible.

Exercise 3 of 3
Review a requirements packet
In the second tool, request the executive summary, personas, functional and non-functional requirements, constraints and assumptions, scope exclusions, and open questions. Look for measurable acceptance criteria and invented decisions. A second answer still needs human review.
Worked example
“The log should be easy to use” is hard to test. “Given an open item, when the incoming lead acknowledges it, then it disappears from the open list and the acknowledgement remains in its history” is testable.
Your turn
Run the handoff and inspect the returned packet. Compare it with the first conversation. If working offline, review the sample above and write a second scenario.
